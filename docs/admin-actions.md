# Admin-Gated Functions — Stellar-Save Contract

## Overview

This document enumerates every admin-gated (privileged) function in the
`stellar-save` Soroban smart contract. For each function it records:

- The **auth guard** pattern used
- Whether a **dedicated authorization test** exists (testing that the
  function rejects unauthorized callers)
- Relevant **runbook** cross-reference

Generated by: Issue #1329 audit (2026-07-29)
Cross-checked against: `docs/runbooks/on-chain-admin-action.md`

---

## Contract-Admin Functions (require contract-level admin)

These functions validate that `caller == ContractConfig.admin`.

| Function | File | Auth Guard | Has Unauth Test | Notes |
|---|---|---|---|---|
| `update_config` | `src/lib.rs` | `config.admin.require_auth()` | ✅ | First-call initializes admin |
| `migrate_storage` | `src/lib.rs` | `caller.require_auth()` + `config.admin == caller` | ✅ | Manual schema migration trigger |
| `update_contribution_limits` | `src/lib.rs` | `admin.require_auth()` + `config.admin == admin` | ✅ | Updates global min/max contribution |
| `add_allowed_token` | `src/lib.rs` | `admin.require_auth()` + `config.admin == admin` | ✅ | Adds token to allowlist |
| `remove_allowed_token` | `src/lib.rs` | `admin.require_auth()` + `config.admin == admin` | ✅ | Removes token from allowlist |
| `require_admin` | `src/migration.rs` | `caller.require_auth()` + `config.admin == *caller` | ✅ | Internal guard used by migration steps |

## Auth Guard Patterns Summary

| Pattern | Description |
|---|---|
| `addr.require_auth()` | Soroban host-level authentication (signature verification) |
| `config.admin == caller` | Contract-level admin check (must match stored admin) |
| `group.creator == caller` | Group-level creator check (must match stored creator) |
| Combination | Both host-auth AND identity check required |
